The proposed fix is to use a next-cycle assertion (|=>) instead of a same-cycle assertion (|->). This will check the result of the multiplication in the next cycle, after the operation has completed.

However, simply changing to a next-cycle assertion is not enough, as we need to make sure that we are checking the result of the correct operation. We need to check the result when the valid output signal is high.

as__ResultCheck3: assert property((valid_i && (op_i == 2'b10)) |=> (mul_unit.valid_o && (result_o == mul_unit.result_2width_def[127:64])));
