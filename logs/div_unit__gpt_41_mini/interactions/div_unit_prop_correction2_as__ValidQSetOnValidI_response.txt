However, in the RTL, valid_q is only updated to valid_i when valid_i is HIGH in the clocked always_ff block. If valid_i is not asserted in the next cycle, valid_q remains unchanged. Also, valid_q is a register updated on the clock edge, so the assertion should consider that valid_q reflects the previous cycle's valid_i. The assertion does not account for the pipeline behavior and the fact that valid_q is registered, so it might not be set exactly one cycle after valid_i is asserted.

Using $past(valid_i) in the postcondition will refer to the valid_i at the precondition cycle, so the assertion should be: (valid_i) |=> (div_unit.valid_q == $past(valid_i)).
